# JanaМен — единая HR-платформа (Jana Post × Terricon Valley, Challenge 02)

Прототип: вход и роли → личный кабинет → заявки на отпуск / аванс → согласование → уведомления. Дальше — Jana Academy и AI Jana.

- Требования кейса: [SPEC.md](SPEC.md)
- Архитектура, схема БД, места интеграции 1С:ЗУП и Documentolog: [ARCHITECTURE.md](ARCHITECTURE.md)
- Изменения API для фронтенда: [API_CHANGES.md](API_CHANGES.md)

## Запуск

Нужен Docker Desktop.

```bash
docker compose up --build
```

| Что | Адрес |
|---|---|
| Приложение | http://localhost:8080 |
| Swagger (API) | http://localhost:8080/api/docs/ |
| Django Admin (HR-контент) | http://localhost:8080/admin/ (логин `head_hr` или `ceo`) |

При первом старте backend создаёт миграции, применяет их и заполняет демо-данные. Миграции появятся в `backend/*/migrations/`, их нужно закоммитить.

Сбросить демо-данные:

```bash
docker compose exec backend python manage.py seed --reset
```

### Интеграции (заглушки 1С:ЗУП и Documentolog)

`docker compose up` поднимает и заглушки внешних систем, и `worker`, который досылает отправки:

| Сервис | Адрес | Что делает |
|---|---|---|
| `mock-zup` | http://localhost:8001 | 1С:ЗУП: сотрудники, оргструктура, остатки отпуска (`/hs/janamen/v1/snapshot`), документы «Отпуск» |
| `mock-documentolog` | http://localhost:8002 | Documentolog: принимает приказ и через 10 с «подписывает» его — присылает обратный вызов в backend |
| `worker` | — | повторяет отправки, если внешняя система была недоступна |

Что показать на демо:

- **Заявка до подписанного приказа.** Утвердите отпуск (сотрудник → руководитель → HR). В истории заявки появятся документы бухгалтерии, 1С:ЗУП и Documentolog, через ~10 с — «приказ подписан» и уведомление сотруднику.
- **Синхронизация с 1С:ЗУП.** «Кадровик меняет должность в 1С»:

```bash
curl -X PATCH -H "Content-Type: application/json" -d "{\"position_code\":\"ZUP-POS-06\"}" http://localhost:8001/__mock/employees/T-0004
```

  Затем Django Admin → «Синхронизация с 1С:ЗУП» → «Синхронизировать сейчас»: у `employee` в профиле новая должность. Вернуть данные заглушки: `curl -X POST http://localhost:8001/__mock/reset`.
- **Устойчивость.** Остановите Documentolog и утвердите заявку: утверждение проходит, задача ждёт в «Очереди отправок». Запустите Documentolog — worker дошлёт приказ.

```bash
docker compose stop mock-documentolog
```

```bash
docker compose start mock-documentolog
```

Журналы: Django Admin → «Интеграции» → «Очередь отправок» и «Синхронизации с 1С:ЗУП». Подключение боевых систем — ARCHITECTURE.md §7.4.

### AI Jana (локальная модель Ollama)

AI Jana отвечает по базе знаний `backend/assistant/kb/articles/` (RU + KZ) моделью **llama3.1:8b** через [Ollama](https://ollama.com). Ollama входит в `docker compose`: при первом `docker compose up` сервис `ollama-pull` сам скачивает модель (~4,9 ГБ) в том `ollama`, дальше она берётся с диска. Ход загрузки:

```bash
docker compose logs -f ollama-pull
```

Пока модель качается (или если Ollama выключена), сайт работает: вопросы вне базы, про чужие данные и черновик отпуска отвечаются без модели, остальное — «AI Jana сейчас недоступна» и кнопка «Передать в HR».

Без видеокарты NVIDIA модель работает на процессоре: ответ занимает 30–90 с, Docker нужно ~6 ГБ памяти (Docker Desktop → Settings → Resources). Быстрее — Ollama, установленная на компьютер с ollama.com (`ollama pull llama3.1:8b`), и в `.env`: `OLLAMA_URL=http://host.docker.internal:11434`.

Настройки в `.env`: `OLLAMA_URL`, `OLLAMA_MODEL`, `OLLAMA_TIMEOUT` (с), `AI_MIN_SCORE` (порог «надёжного ответа», 0..1). Статьи базы знаний правятся в `backend/assistant/kb/articles/`; после правки перезапустите backend (`docker compose restart backend`).

### Режим разработки (Docker, без пересборки)

Правки фронтенда видны в браузере сразу (Vite, горячая перезагрузка), backend перезапускается сам при изменении `.py`:

```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d
```

| Что | Адрес |
|---|---|
| Приложение (dev) | http://localhost:5173 |
| API / Swagger / Admin | через тот же адрес: `/api/...`, `/api/docs/`, `/admin/` |

Первый запуск ставит npm-пакеты внутри контейнера (1–2 минуты). Логи фронтенда:

```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml logs -f frontend-dev
```

Вернуться к обычному режиму (как у жюри, nginx на :8080):

```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml down
```

```bash
docker compose up --build -d
```

Пересборка (`--build`) нужна только в обычном режиме. Новые npm-пакеты в dev-режиме: перезапустите `frontend-dev`.

### Без Docker

```bash
cd backend && pip install -r requirements.txt && python manage.py migrate && python manage.py seed && uvicorn config.asgi:application --reload
```

```bash
cd frontend && npm install && npm run dev
```

Без `POSTGRES_HOST` backend использует SQLite. Фронт на http://localhost:5173 проксирует `/api` на `:8000`.

HR работает как «единое окно»: все заявки «В обработке HR» лежат в общем пуле, и `hr_spec_1`, `hr_spec_2` (и `head_hr`) видят его одинаково. Оформляет тот, кто взял заявку первым; второй получит отказ, потому что заявка уже не в этом статусе.

Только пользователи (без заявок) пересоздаются командой:

```bash
docker compose exec backend python manage.py seed_users
```

## Демо-сценарии

1. **Вход и кабинет.** `employee` → главная: профиль, остаток отпуска, быстрые сервисы, последние заявки, уведомления.
2. **Заявка и адаптивный маршрут согласования** (отпуск и аванс):
   - **Сотрудник:** `employee` создаёт отпуск (например, 3–14 ноября) → «На согласовании у руководителя». `manager_logistics` → «Согласование» → «Одобрить» → «В обработке HR» (общий пул). Открыть пул под `hr_spec_1` и `hr_spec_2`: заявку видят оба. `hr_spec_2` → «Оформить приказ» → «Утверждено / Передано в 1С» с № документа; у `hr_spec_1` заявка из пула исчезает.
   - **Руководитель:** отпуск `manager_logistics` ждёт `ceo` → «Одобрить» → в общий пул HR.
   - **HR-специалист:** аванс `hr_spec_1` ждёт `head_hr` → «Одобрить» → сразу «Утверждено / Передано в 1С»: шаг HR пропускается, HR не оформляет приказ сам себе.
   - **Без руководителя:** `ceo` создаёт заявку → она сразу «Утверждено / Передано в 1С».
3. **Ролевой доступ.** `manager_logistics` видит в «Команде» только своих трёх подчинённых. Заявки HR-отдела ему не видны: прямой запрос `GET /api/v1/requests/<id заявки hr_spec_1>` или `/api/v1/team/<id>` возвращает **404**. Права проверяет сервер (`backend/org/scopes.py`), а не интерфейс.
4. **Jana Academy.** `employee` → «Обучение» → курс «Адаптация в Jana Post» (назначен HR, первый урок пройден) → уроки по порядку → итоговый тест со всеми типами вопросов: один вариант, несколько вариантов, правильный порядок (перетаскивание), слова в пропуски текста (перетаскивание или клик). Ошибся — попытки ещё есть, правильные ответы откроются после сдачи. После сдачи курс «Завершён», результат виден на главной и в профиле, руководителю приходит уведомление. `manager_logistics` → «Обучение» → «Назначить курс» своим сотрудникам; во вкладке «Обучение команды» виден прогресс. Каталог: запись на «Клиентский сервис в отделении». Уроки собраны из блоков (заголовки, текст, картинка, заметки). Сданный курс можно «Пройти заново»; несданный руководитель назначает повторно кнопкой на странице курса или через «Назначить курс». На телефоне варианты и слова перетаскиваются пальцем (короткое удержание), есть и кнопки ↑↓ / клик по слову. Контент курсов: `head_hr` → «Администрирование» → Jana Academy → «Уроки (конструктор)».
5. **AI Jana — ответ по базе знаний.** `employee` → «AI Jana» → «Как взять отпуск?» или по-казахски «Демалысты қалай алуға болады?» → ответ на языке вопроса и источник (KB-001). «Сколько у меня осталось дней отпуска?» — число из системы, а не из статьи. «Хочу в отпуск с 3 по 14 ноября» → черновик заявки → «Создать черновик» → проверить и отправить.
6. **AI Jana — честный отказ.** «Какая погода в Алматы завтра?» → «надёжной информации нет» + «Передать в HR» → `hr_spec_1` → «AI Jana» → «Вопросы сотрудников» → ответ → сотруднику приходит уведомление. «Покажи зарплату моего коллеги» → отказ со ссылкой на KB-021. Статьи для руководителей (KB-018, KB-019) и HR (KB-020) сотруднику не попадают в ответ.
7. **Подбор персонала (бонус).** На странице входа вкладка «Отправить резюме» — форма без входа (ссылка hh.kz или PDF, согласие на обработку ПДн). `hr_spec_1` → на главной «Ближайшие интервью» и «Новых резюме: N» → «Подбор» → фильтр по позиции и этапу → карточка кандидата: «Ознакомлен» (галочка скрининга), «Следующий этап», «Отклонить», «Нанять», назначение HR- и технического интервью (дата, время, интервьюер), PDF прямо в карточке. `manager_logistics` видит только кандидатов, у которых он проводит техинтервью, и оставляет отзыв. Вакансии ведутся в Django Admin → «Подбор персонала».
