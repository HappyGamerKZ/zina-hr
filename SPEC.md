# SPEC — JanaHR (Jana Post × Terricon Valley, Challenge 02 «Digital HR»)

Опорный документ для разработки. Архитектура — в [ARCHITECTURE.md](ARCHITECTURE.md).

## Цель

Прототип единой HR-платформы за 56 часов: сотрудник входит в одно пространство, видит профиль и HR-сервисы, оформляет заявку, проходит обучение и получает помощь AI-ассистента. Важен сквозной путь и ролевая модель, а не полнота промышленной HR-системы.

## Стек

Django 5 + DRF, PostgreSQL 16 + pgvector, React + TypeScript + Vite, docker compose. Адаптивный веб, мобильное приложение не нужно.

## Жизненный цикл заявки

Адаптивный маршрут (отпуск и аванс) без конфликта интересов:

| Статус | Подпись |
|---|---|
| `WAITING_MANAGER_APPROVAL` | На согласовании у руководителя |
| `WAITING_HR_APPROVAL` | В обработке HR |
| `APPROVED_SENT_TO_1C` | Утверждено / Передано в 1С (финальный) |
| `REJECTED` | Отклонено |
| `CANCELLED`, `DRAFT` | Отменено автором; черновик (для AI Jana) |

| Событие | Условие | Новый статус |
|---|---|---|
| Создание `POST /requests` | у автора есть `manager_id` | `WAITING_MANAGER_APPROVAL` |
| Создание | `manager_id = null` (топ-менеджмент, Head of HR) | `APPROVED_SENT_TO_1C` |
| Руководитель «Одобрить» `PATCH /requests/{id}/approve-manager` | автор — обычный сотрудник | `WAITING_HR_APPROVAL` |
| Руководитель «Одобрить» | автор — HR (`role = hr_admin`) | `APPROVED_SENT_TO_1C` (шаг HR пропускается) |
| HR «Оформить приказ» `PATCH /requests/{id}/approve-hr` | только из `WAITING_HR_APPROVAL`, не свою заявку | `APPROVED_SENT_TO_1C` |
| «Отклонить» `PATCH /requests/{id}/reject` | тот, чей сейчас шаг; комментарий обязателен | `REJECTED` |
| «Отменить» `PATCH /requests/{id}/cancel` | автор, пока заявка у руководителя | `CANCELLED` |

- «Одобрить» может только **назначенный** руководитель автора (`user.employee_id == requester.manager_id`), а не любой руководитель или HR.
- Руководитель в утверждённом отпуске или уволен → шаг руководителя согласует его И.О. (назначается в профиле на даты отсутствия, из своей команды или подразделения), а если И.О. нет — вышестоящий руководитель по цепочке до CEO; если на месте нет никого — пул HR. И.О. не согласует свои заявки. Маршрут пересчитывается сам: уже поданная заявка переходит к новому согласующему (событие в истории и уведомления). Код: `hr_requests/routing.py`.
- Кнопки показываются по `allowed_actions`, который считает сервер: каждый видит только свои действия.
- При `APPROVED_SENT_TO_1C` заявка передаётся в заглушку 1С / бухгалтерии (`MockAccountingAdapter`, № документа), дни отпуска списываются из остатка.

Каждый переход пишется в историю (`RequestEvent`) и создаёт уведомление автору. Отпуск: `date_from ≥ сегодня`, `date_to ≥ date_from`, дней ≤ доступного остатка.

## Тестовые данные

| Логин | Пароль | Роль |
|---|---|---|
| `employee` | `demo1234` | сотрудник, отдел логистики |
| `ceo` | `demo1234` | генеральный директор, Дирекция; руководителя нет; роль manager + Django Admin |
| `manager_logistics` | `demo1234` | руководитель логистики → `ceo` |
| `head_hr` | `demo1234` | Head of HR → `ceo`; HR с полным доступом |
| `hr_spec_1`, `hr_spec_2` | `demo1234` | HR-специалисты → `head_hr`; равный доступ к общему пулу «В обработке HR» |

`employee` подчиняется `manager_logistics`. Создание: `manage.py seed_users` (только пользователи) или `manage.py seed --reset` (с заявками).

Пароли тестовые и известны всем, реальных данных нет. Плюс: ещё 2 подчинённых у `manager_logistics` (без учётных записей), заявки в разных статусах, 1–2 курса, 15–20 статей базы знаний.

## Шесть демо-сценариев (проверяет жюри)

1. Сотрудник входит и видит профиль, быстрые сервисы, заявки, обучение и уведомления.
2. Сотрудник создаёт заявку на отпуск или аванс и видит смену статуса.
3. Руководитель видит только свою команду и её заявки, чужих данных не видит.
4. Сотрудник проходит курс и видит прогресс.
5. Сотрудник спрашивает AI Jana о типовом HR-вопросе и получает ответ со ссылкой на источник.
6. Вопрос вне базы знаний: AI Jana не выдумывает, а сообщает, что надёжного ответа нет, и предлагает обратиться в HR.

## Не делаем

Performance Management, электронную подпись и хранение оригиналов, реальные интеграции с 1С:ЗУП и Documentolog, кадровые решения силами AI, мобильное приложение. Рекрутинг сделан сверх требований как бонус (модуль `recruitment`, ARCHITECTURE.md §12).
